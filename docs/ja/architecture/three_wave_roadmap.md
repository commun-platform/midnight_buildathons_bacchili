## 3段階の進め方

| Wave | 検証する問い | 到達点 |
| --- | --- | --- |
| Wave 1 | 非公開のしきい値証明という中核価値が成立するか | Core Proof PoC |
| Wave 2 | 実際の現場計測システムで安定運用できるか | 企業との運用パイロット |
| Wave 3 | 反復可能な顧客価値と商用提供条件を検証できるか | PMF検証に向けた商用準備と継続売上Evidence |

## Wave 1 — Core Proof PoC

Wave 1は、ユーザーが認可したブラウザクライアントを使い、疑似計測元から非公開しきい値証明の中核価値を検証します。
疑似の日次計測データを作成し、その時間別Summaryを認可済み運用DataとしてTrustedな管理Backendへ保存します。
計測期間より前に登録した判定条件との関係を第三者へ元の値を公開せずに証明してMidnightへ記録します。疑似Raw値と
Private Proof OpeningはBrowser Privateな計測元に残します。

審査画面は、証明の流れを一か所で確認できるよう、運用者操作と第三者検証を意図的に一つへまとめています。これは
審査用PoCであり、本番における画面、組織、役割の最終的な分離ではありません。

Wave 1で確認する内容：

- 証明対象と公開判定条件の登録
- 疑似の日次計測データ生成
- 時間別運用Summaryの認可済みBackend保存
- 固定形状の非公開日次入力への集約
- 証明生成とサービス側手数料負担による取引送信
- 公開判定結果と証拠識別子のMidnight記録
- PoC処理を確認する運用者向け表示
- 元の値を見せずに結果を確認する第三者向け表示

現場側Runtime、認証、配布、復旧に関する補助実装もリポジトリに含まれますが、長期間の自律的な現場運用はWave 1の
主要審査経路ではなく、本番サービスとして完了したとは主張しません。

Wave 1では、Wave 2の運用成熟Gateに先行して、Wallet不要のManaged Cloud受付、Access保護された運用Console、
Redact済みAudit／日次Metric、障害／Receipt通知、非公開Read-only Support MCP、別Workerの公開TX検証MCPも
実装しました。これらはTest済みの現行機能ですが、存在するだけでWave 2のPartner運用成果を満たすものではありません。

Wave 1の成功条件は、審査員が疑似データを使う一連の証明フローを再現し、証明できること、非公開にすること、証明しない
ことを明確に理解できることです。

## Wave 2 — Operational Partner Pilot

Wave 2は、証明フローを実際の現場計測システムへ接続し、日次処理を自律的に安定運用できる状態へ進めます。計測、集約、
証明の予定実行、取引送信、状態確認、再試行、復旧までを、日常的な手動操作なしで継続させます。

製品面の目標：

- 運用者、第三者検証、システム運営者向けApplicationの本番分離を完成
- 組織、プロジェクト、役割単位の認証・認可
- 実装済みのAudit Trail、診断、処理Metric、Health監視、運用Console、通知、Support自動化を
  Partner負荷で検証・強化
- 上限付き非同期処理、冪等な再試行、障害復旧、通知
- 複数の現場計測元に対するLifecycle管理
- 制御されたソフトウェア更新とRollback
- 運用データとログの保持・秘匿化規則

事業面では、関連する業務を既に運営している企業とパートナー実証を行います。実際の帳票・管理業務へ接続し、運用原価、
顧客価値、成立する価格を検証して、研究目的の実演ではなく有償パイロットへの移行を目指します。

Wave 2の成功条件は、合意した検証期間中、パートナー企業が自律生成された日次証明を実業務で利用し、信頼性、支援工数、
Security／Tenant分離、商用上の評価を測定できることです。Source実装だけではこのGateを満たしません。

## Wave 3 — Trust Minimization and Commercial Readiness

Wave 3は、ハードウェアに保護された識別情報・鍵、実行環境の完全性Evidence、校正やLifecycle Eventの検証可能な来歴を
導入し、計測元とそのソフトウェアに必要な信頼を減らします。これらは計測元の識別とソフトウェアの完全性を強化しますが、
それだけで物理計測値の真実性を証明するものではありません。

製品面の目標：

- ハードウェアに保護された識別情報と署名権限
- 承認済みソフトウェア・設定状態のEvidence
- 校正、保守、交換、更新の来歴
- 複数組織・複数現場での商用運用
- 標準的な外部連携、SLA、Backup、Disaster Recovery
- 利用量計測、Plan、Billing、Support運用

事業面では、PMFを主張する前に、その検証へ進める商用準備を整えます。実売上、反復利用、契約更新、追加現場・追加計測元への
拡大、継続提供可能なUnit Economicsを確認します。既存の業界パートナーと、その運用・販売チャネルを主要な導入経路とします。

Wave 3の成功条件は、複数の有償顧客が再現可能な価値を得て、少なくとも1社が契約更新または利用拡大し、次のPMF検証へ進むための
顧客価値・提供体制・Unit EconomicsのEvidenceが揃うことです。一度だけの売上は商用Evidenceですが、それだけでPMF達成とは
判断しません。Wave 3の到達点もPMF達成そのものではなく、PMFを再現可能な形で検証する準備状態です。

## 用語の抽象度

ロードマップと提出資料ではCapabilityで表現します。

| Capability表現 | 意味 |
| --- | --- |
| ユーザーが認可したブラウザクライアント | Wave 1審査で利用するクライアントとユーザー管理アカウント |
| 疑似計測元 | PoC検証用の合成データ生成主体 |
| 現場計測システム | 特定のコンピューターや基板に依存しない、本番の計測元 |
| 管理されたバックエンド | 認証、Workflow、永続化、証明実行、運用機能 |
| サービス側手数料負担 | 特定のToken機構名に依存しない取引手数料の負担方式 |
| ハードウェア保護Identity | 特定製品に依存しない、持ち出せない識別情報とAttestation能力 |

Midnightとゼロ知識証明は製品の中核なので明記します。具体的な製品、Infrastructure Service、Algorithm、参照Hardwareは、
再現性のために必要な実装・運用文書だけで使用します。
