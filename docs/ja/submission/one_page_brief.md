# BACCHIRI!━━Verifiable Measurement Layer

## 顧客に提供する価値

**センサー値を第三者に見せず、登録済みしきい値の範囲内かどうかを証明します。**

建設現場の計測結果は、機器提供会社、レンタル会社、施工会社、発注者、監査者など複数の組織で使われます。しかし、確認のために生の測定値を渡すと、必要以上の情報開示になります。

BACCHIRI!━━Verifiable Measurement Layerは既存の計測機器や管理システムを置き換えず、値を隠したまま判定を確認できる証明層を追加します。

![センサー値を開示せず、しきい値判定を確認する](../assets/review/privacy-value-proposition-ja.png)

## 公開する情報と公開しない情報

| 公開しない | 公開する |
| --- | --- |
| 生のセンサー値 | 対象日と対象デバイス |
| 時間別の最小値・最大値 | しきい値（下限・上限・単位） |
| 証明用乱数 | 観測した時間帯と件数 |
| デバイスの署名鍵とウォレット情報 | 範囲内／範囲外／停止の判定結果、Midnight取引記録 |

## 動き方

1. エッジデバイスが生のセンサー値を収集し、端末内に保持します。
2. 1時間ごとの最小値・最大値にまとめ、1日を24個の時間枠にそろえます。
3. バックエンドが証明依頼を受け付け、センサー値を公開せずに証明を生成します。
4. エッジデバイスがMidnight取引に署名します。
5. 第三者は、対象日、公開しきい値、判定結果、取引記録を確認します。

## Wave 1で検証済みの内容

- 6つの証明回路がすべてコンパイル成功。
- 9つの構成領域にまたがる288件の自動テストがすべて成功。
- 型検査、ビルド、Cloudflare配備前検査が成功。
- 2026-08-28のMidnight事前公開ネットワーク記録で、範囲内と範囲外の両方を確認。
- 1日1,440件の測定値を、24個の時間枠を使う1件の日次証明へ集約。

## この証明だけでは分からないこと

物理センサーが正しい値を出したか、24時間連続して測定したか、エッジデバイス側の集計が正しいかは証明しません。また、現行構成ではバックエンドが証明生成中の最小値・最大値を信頼して処理します。

第三者画面は公開記録を表示しますが、ブラウザ単体でゼロ知識証明を再検証する機能はWave 2の計画です。

## 導入への道筋

まず建設現場の温度計測で実証実験を行い、既存の計測機器と販売・レンタル網へ組み込む計画です。Wave 2はLocal／複数Source照合の強化と運用自動化、Wave 3は校正情報付きデバイス証明とセキュアハードウェア連携を計画しています。
