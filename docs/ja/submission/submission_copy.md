# Wave 1 提出文

[English](../../submission/submission_copy.md)

## プロジェクト名

BACCHIRI!━━Verifiable Measurement Layer

## 一言で言うと

センサー値を第三者に見せず、登録済みしきい値の範囲内かどうかを証明します。

## 短い説明

BACCHIRI!━━Verifiable Measurement Layerは、エッジデバイスの1日分の測定値を1時間ごとの最小値・最大値にまとめ、値を隠したまましきい値判定を作ります。生の測定値はエッジデバイスに保持します。証明生成後、エッジデバイスがMidnight取引に署名し、範囲内または範囲外の結果を記録します。測定値がない時間は、範囲内とは扱わず「停止」として公開します。

## 課題

計測結果は管理画面、CSV、帳票、クラウドシステムを通じて共有されます。建設業界では、騒音、振動、温度などの帳票を、機器提供会社、レンタル会社、施工会社、発注者、監査者など複数組織が利用します。そのため、確認者は帳票を作った組織やシステムを信頼するしかない場合があります。本プロジェクトが暗号学的に確認する問いは、「対象日の時間別最小値・最大値が、運用前に登録したしきい値を満たしたか」です。

## 解決方法

- エッジデバイス：生のセンサー値と時間別の最小値・最大値を保持し、API認証とMidnight取引への署名を行います。
- 画面：管理者の操作画面と、秘密値を見せない第三者確認画面を提供します。
- バックエンド：デバイス認証、証明依頼の受付判定、公開記録の保管、証明生成を担います。
- Midnight：公開しきい値、対象デバイスとの紐付け、確定済み判定結果、取引記録を保持します。

## Midnightを使う理由

「公開しない値」と「誰でも確認できる判定記録」を分けられるからです。時間別の最小値・最大値と証明用乱数は非公開です。公開するのは、対象日、しきい値、対象デバイス、観測時間、件数、判定結果、取引記録です。判定に使うしきい値は証明時に自由指定せず、運用開始前に登録した値を使います。

## 正確に何を証明するか

確定済み日次証明は、観測した各時間の非公開の最小値・最大値が、登録済みしきい値の範囲内であること、または少なくとも1時間が範囲外であることを証明します。同時に、対象日、観測した時間帯、件数、対象デバイス、登録済みしきい値、証明入力のコミットメントを紐付けます。

物理センサーの真正性、連続測定、未提出データがないこと、デバイス側集計の正しさは証明しません。現行構成では、バックエンドと証明サーバーを信頼対象とします。ブラウザは公開情報を表示しますが、ゼロ知識証明の独立再検証やMidnightの直接照会はまだ行いません。

## 対象利用者と導入

最初の事業ユースケースとして協議しているのは建設現場の計測結果検証です。Wave 1で検証済みなのは温度計測の経路です。騒音や振動などに展開するには、計測種別ごとのしきい値定義、入力形式、検査規則の追加が必要です。新しい機器や販売網を一から作るのではなく、既存の計測機器とクラウド運用へ検証機能を追加します。

既存の機器と販売・レンタル網を利用する現場実証に向け、業界事業者と協議を進めています。これは事業化の進捗であり、完了済みの技術検証ではありません。同じ証明の仕組みは将来、低温物流、食品・医薬品保管、研究設備、規制対象設備にも展開できます。

## 3段階の展開計画

- Wave 1 — 検証済み: デバイス認証付き日次証明、1日を24時間枠で集約、Midnight事前公開ネットワークで範囲内／範囲外を確認、管理者／第三者画面。
- Wave 2 — 計画: ブラウザでの独立検証、署名付き来歴証明、運用自動化、障害復旧と複数デバイス監視。
- Wave 3 — 計画: 校正情報付きデバイス証明、ファームウェア識別情報、セキュアハードウェア連携、組織横断監査。

現行ブラウザはMidnightを独立検証しません。校正情報とファームウェア識別情報の紐付けも、現行機能ではなく計画です。
